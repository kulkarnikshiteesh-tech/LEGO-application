## 1. Deployment architecture (REUSE THIS for the Design Manager page)

Goal Kshiteesh set: **one repo, multiple Vercel projects, separate URLs, and nobody can discover the other applications.**

How it works now:
- One **private** repo (`LEGO-application`). Root holds the older "Since Last Application" page (`index.html` + `assets/`, deployed at `lego-application.vercel.app`).
- Each new application lives in **its own subfolder** (`product-owner/`, and `design-manager/` when built).
- A repo-root **`.vercelignore`** lists `product-owner` and `design-manager` so the **root** Vercel project never builds or serves them. Verified: `lego-application.vercel.app/product-owner/` returns **404**.
- Each application is its **own Vercel project** deployed via the **Vercel CLI** from its local folder, so only that folder's files are uploaded. Total isolation.

**To deploy a new app (e.g. design-manager):**
1. `cd` into the app folder, then `vercel link --yes --project lego-design-manager` (lowercase name required).
2. `vercel --prod --yes` → returns a deployment URL.
3. `vercel alias set <deployment-url> lego-design-manager.vercel.app` for a clean URL.
4. Add a root `.vercelignore` entry (already covers `design-manager`).
5. Copy the app into `LEGO-application/design-manager/`, commit, push (repo is private).
6. Add a project-level `.vercelignore` inside the app folder to exclude internal notes (`content-stories.md`, `BUILD-STATE.md`, `.vercel`) from the public deploy.

Vercel CLI is installed and logged in as `kulkarnikshiteesh-tech`. `gh` is NOT installed; use plain `git` (credentials cached). Repo visibility can only be changed by Kshiteesh in GitHub settings.

**Gotchas learned:**
- A public repo CANNOT be isolated (folders are browsable on GitHub). Repo must be private.
- Deploying the whole folder exposed `content-stories.md` / `BUILD-STATE.md` at the public URL → fixed with project `.vercelignore`. Always exclude internal notes.
- Filenames/folders with spaces work on Vercel when URL-encoded (`%20`). An apostrophe in a filename was renamed out to be safe.
- Prune unused assets before deploy (the shared `assets/` had ~90MB of unused product videos; trimmed to the 4 files actually referenced).

## 3. KIDO — the signature interactive system (REUSABLE, technical notes)

KIDO is one robot character that is the spine of the page.

- **Hero game:** 5x5 grid, KIDO (squircle robot, glossy visor, blinking eyes), an apple, a house. Direct up/down/left/right control (triangle-in-circle buttons, plus reset). Walk to the apple, carry it home → confetti + happy KIDO + the hero scroll-cue flips to "scroll on, he follows you." Arrow keys work too. The grid mirrors the real No-code Robot board.
- **Continuity (the magic):** KIDO is a single `position:fixed` element (`#kido`). It lives in the grid; on scroll past the hero he **walks out to the station rail** and rides it; scroll back up and he **walks back into his exact remembered cell**. His grid position persists the whole session.
- **Implementation:** mode is `grid` vs `rail`, decided by whether the board is on-screen (`getBoundingClientRect`), NOT by scroll distance (that fix stopped him landing in random cells). Transition is `none` while glued-tracking the grid on scroll, animated (`WALK_T`) during the grid↔rail walk and on the rail. `STEP_T` for in-grid button hops. A short "walk wobble" plays during the transition.
- **Rail:** a fixed left station rail (desktop >1240px) with section names + a yellow→red fill line; mobile gets a sticky chip bar. Section content is shifted right (`margin-left:300px` desktop) so the rail never overlaps copy.
- **Speech bubbles:** on the rail, KIDO pops a short dry one-liner per section (e.g. "Data picks the bet.", "Same system, every kit.", "That penguin is me."). Bubble only on the rail, auto-hides.

## 4. Other interactions

- **Staggered reveals:** grouped content (stats, galleries, why-cards, proof, etc.) cascades in item by item.
- **Hero cursor glow:** a soft blue light follows the cursor across the hero card (uses CSS vars; deliberately does NOT move the board so KIDO stays glued).
- **Count-up stats** (`data-count`, with prefix/suffix for ₹ and %).
- **Galleries** use `object-fit:contain` on a dark panel so whole products are visible (after before/after sliders were found to crop badly — sliders were removed).
- **Store tiles:** logos framed on identical fixed-height plates (white for MakerVerse, teal for OIMake) so the two cards match exactly.
